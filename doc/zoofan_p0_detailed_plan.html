P0 要做

  • 动物园与来源 Registry
  • 可中止、可限额、可审计的爬虫
  • 文章清洗、canonical 去重、图片元数据
  • AI 选题评分与候选池
  • 小红书标题 / 正文 / 标签 / 配图建议
  • 人工审核台 + 发布记录
  • 表现数据回填 + 每周复盘

P0 明确不做

  • 用户注册 / 登录
  • 用户端新闻网站
  • 原生 App
  • 图片社区 / 评论 / Follow
  • 复杂推荐算法
  • 为了“全自动”而开发高风险的小红书自动登录机器人
  • 过早迁移到复杂云架构

7 个工作流

展开查看任务和验收条件；勾选后实时计算进度。
进度0%
WS1 · Crawler Hardening — 先解决无限爬和不可控
任务
  • source 级抓取预算与 hard stop
  • canonical URL 标准化
  • 过滤分页 / 日历 / 搜索陷阱
  • 连续 3 页无新增 URL 自动停止
  • wall-clock timeout + 最大请求数
  • 有限 retry，不允许无限 retry
  • run stats 写入 stop_reason
推荐默认预算
  • 50 新文章 / source / run
  • 200 discovered URLs 上限
  • 20 pagination pages 上限
  • 180 秒 / zoo

验收：10 家不同结构动物园连续跑 3 次，无无限循环；每次都能解释为什么停止。

WS2 · Data Quality — 让数据库真正能做内容
  • title / body / published_at / language 标准化
  • canonical + content_hash 双层去重
  • article ↔ zoo identity 稳定关联
  • 图片 URL、alt、caption、source、尺寸入库
  • raw_html 继续作为可追溯证据
  • crawl 后自动生成 quality report

验收：≥95% 有 title + canonical_url；≥90% 能识别 zoo；重复文章不重复进入候选池。

WS3 · Zoo Scale-up — 分三层扩张
  1. 10 家：验证 crawler 类型覆盖、预算与停止机制
  2. 30 家：验证数据模型与 daily batch 稳定性
  3. 60–100 家：验证内容供给丰富度

验收：启用来源批次成功率 ≥85%；异常 source 可以独立 disable，不拖垮整批。

WS4 · Content Intelligence — 从 Article 变 Candidate
  • event_type：出生 / 死亡 / 转移 / 新展区 / 保护 / 研究 / 运营
  • animal_species / animal_name
  • summary_zh
  • novelty / emotion / rarity / freshness
  • xhs_fit_score / overall_score
  • reason_to_publish

评分 v0：35% 趣味/情绪 + 25% 稀缺 + 20% 新鲜度 + 20% 小红书适配。

人工队列：overall ≥75 或命中强事件类型。

WS5 · XHS Package Generator — 生成可审核内容包
标题
事实型 / 情绪型 / 悬念型 3 版
正文
中文重写、保留事实、不编造细节
素材
候选图片、来源、使用风险备注

同时生成 hashtags、动物园/城市标签、封面短句、原文 URL、事实核对清单。

验收：≥70% 内容包只需轻改；目标人工编辑 ≤10 分钟。

WS6 · Review & Publishing — 人工确认作为 P0 风控层
  • 事实：时间、动物、数量、地点
  • 来源：原文可回溯
  • 图片：来源与使用风险可见
  • 表达：避免夸大、误导与机器味

P0 不把自动登录并自动发小红书作为核心目标：先证明内容运营模型。

WS7 · Analytics Loop — 让反馈反过来训练选题
每篇发布记录
  • published_at / xhs_post_id / package_id
  • views / likes / saves / comments
  • 24h / 72h / 7d snapshots
  • event_type / animal / zoo / title_style
每周只回答 4 个问题
  1. 哪类事件最容易被收藏？
  2. 哪些动物互动最高？
  3. 哪种标题结构更稳定？
  4. 哪些 source 抓很多却不产好内容？

6 周执行节奏

先稳定 → 再扩张 → 再验证内容。每周必须有 Exit Criteria。

Week 1 · Crawler 稳定性10 zoos

budgets、stop_reason、分页陷阱、重复陷阱、source disable、回归测试。

Exit：10 家 × 3 连续运行，无无限循环；每家都有 run report。

Week 2 · 数据质量 + 扩到 30 家30 zoos

canonical、content hash、日期、语言、media、zoo identity、quality report。

Exit：30 家 daily run 稳定；重复内容不重复进入下游。

Week 3 · AI 选题层Candidate Queue

事件分类、动物实体、中文摘要、评分、reason_to_publish、每日 Top stories。

Exit：运营时不再需要人工扫整个 articles 表。

Week 4 · 小红书内容包 + 审核台Draft → Ready

标题 A/B/C、正文、hashtags、配图建议、来源卡、事实清单、approve/reject/edit。

Exit：候选 → ready package 机器 ≤2 分钟，人工 ≤15 分钟。

Week 5 · 发布运营 + 数据回流4–7 / week

publication_records、24h/72h/7d 快照、每周内容复盘。

Exit：可以按 zoo / animal / event / title_style 比较表现。

Week 6 · 60–100 家 + P0 GateDecision

扩大 source，跑完整闭环，核算人工成本、候选产量、题材规律、技术稳定性。

Exit：满足 Gate 才进入 P1 Web；否则继续优化 P0 的瓶颈。
